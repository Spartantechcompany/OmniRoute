- **fix(video):** `preserveVideoUrl` (#9248) can now actually be set. The per-model flag that keeps `video_url` content parts for video-capable models (e.g. Qwen-VL behind an OpenAI-compatible provider) shipped backend-only: `PUT /api/provider-models` dropped the key, the per-protocol schema rejected it, and the resolver ignored the model's own custom-model row. The endpoint and schemas now accept it (`true` / `false` / `null` to clear), the resolver reads the custom-model row before the legacy and per-provider compat entries (existing values keep applying), and the model Compatibility popover has a "Pass video_url to the model" toggle. The built-in default is unchanged: only Moonshot and Kimi preserve `video_url` unless a model opts in.
- **fix(video):** the input-token estimate no longer measures inline video and audio payloads as prompt text. A ~450 KB clip sent as a `data:video/...;base64,` URI was estimated at ~150k tokens and rejected against a 128k window while the upstream model counted ~550. `video_url` / `input_video` / `video` and `input_audio` / `audio_url` / `audio` with inline base64 are now priced with a bounded per-part budget, like inline images and documents already were; remote URLs and plain text keep their text cost.
